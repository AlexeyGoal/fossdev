## Запуск на локальной машине через 127.0.0.1

При запуске без Docker каждый сервис приходится стартовать отдельно командой `poetry run` с указанием порта. Это неудобно — команды получаются длинными, а запоминать, какой порт к какому сервису относится, не всегда просто.

## Ошибка при запуске контейнера с 127.0.0.1

Если внутри контейнера использовать адрес `127.0.0.1`, он будет ссылаться на сам контейнер, а не на хост-систему. Поэтому подключиться к сервисам на основной машине не получится.

## Успешное взаимодействие контейнеров через имена сервисов 

Docker Compose автоматически создаёт общую сеть, в которой контейнеры могут обращаться друг к другу не по IP, а по именам, указанным в `docker-compose.yml`. Это удобно и надёжно.

## Необязательное взаимодействие через хост с использованием host.docker.internal.

Если сервис внутри контейнера должен обратиться к программе, запущенной на самой операционной системе (не в Docker), используется специальный адрес `host.docker.internal`.
